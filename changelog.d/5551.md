Package 2.1409 (Bündel: Versionsdaten beim Abbild-Bau ableiten statt Versi, Sammelpaket: Aufgaben ohne Paket (Dispatcher)).

### Added
- Kalmido AI per organisation (#6363): the Kalmido AI (agents on the Kalmido server) works in an organisation only after one of its admins switches it on (Settings > Organisation > People, the organisation's entry: *Kalmido AI in this organisation*; `PATCH /api/orgs/{id} {"server_agents": true}`). Off by default: until then no content of the organisation goes to the AI provider; creating a team server agent, its server settings, model list and starter pack answer 403 `org_server_agents_off`, and a run ends before any provider call with a note to the person who asked. Every change is a security alert to the server's admins. Organisations that already used a team server agent (or a server agent of one of their admins) keep it on.
- Release build (#6893): `tools/stamp_release.py X.Y.Z` derives VERSION, the shell cache number of `static/sw.js` (from the version, always rising), the CHANGELOG section and the "What's new" entry from the tag and the `changelog.d` fragments since the tag before; it does nothing while the tree already says that version.

### Changed
- Release workflows (#6893): `release.yml` stamps the tagged tree before the image build and checks tag = stamped VERSION, the notes come from the stamped CHANGELOG; `weekly-release.yml` stamps the CHANGELOG sections before its notes and the tagged tree before the web manifest.
- CI gate (#6893): a tag on a commit the merge queue landed gets its image when the check "Merge queue gate" of that commit's merge_group run is green; the landing push alone (stage none) still gives no image.
- Privacy template and the outgoing connections list of SELF-HOSTING.md name the Kalmido AI at Anthropic (USA) with what a run sends, VIES, FinTS, Paperless and Linear, and complete the Git (issue sync) and e-mail rows; AGENTS.md no longer says that Kalmido never starts AI processes (#6363).

### Fixed
- The update check setting says "every 6 hours" instead of "daily", as the server checks (#6363).
- MCP `get_task` and `list_subtasks` also fence a task or subtask of the owner whose title or description another account (or a webhook, a public link, a sync) wrote last, judged by `updated_by` (#7124).
- Files that came from a mail or a public form before 2.1391.0 are marked as from outside once at the start, so the API no longer names the task's creator as their uploader and agents read their names as data (#7124).
