Package 2.1465 (Bündel: Sammelpaket: Aufgaben ohne Paket (Dispatcher)).

### Changed
- #7309: One shared place answers "where is a module on for me" and "where does a new entry go" (accounts/wsplace.py wsp_spaces / wsp_new); the browser reads its lists from /api/state (wsp, wsp_w) instead of computing them. A new client, calendar, address book, contact, upload or share names its workspace; with several possible workspaces the dialog asks (required choice), the server answers 400 space_needed instead of silently picking Private or the first organisation. Nothing lands where the module is switched off for the person.
- #7309: Move to another workspace offers only workspaces where the module is on and writable; a move without a target is refused (was Private). Trip expenses from Home, a device into the own office and form-created clients respect a switched-off office / clients module.
- #7309: Switching off "Also private" for Office & finance names what keeps running there (invoice series, bank and card reminders); nothing is stopped.
- #7309: API v1 clients, event calendars and address books take `space`; the OpenAPI text no longer says "default: your first". Without a name the server takes the workspace on top, the only one, or (transition, #7385) the only writable organisation where the module is on.
- #7313: Every office request names the office it shows: the server takes the object's office, then the named area, then the setting, and never guesses between several offices (400 office_no_area). Client card, portal link, palette, start tile, Settings > Company & office, exports, signature, search and suggestion agents work in the shown office; links into the office carry their area; caches and late answers are kept per office.
- #7313: Under "All workspaces" with exactly one office on, that office opens (as before); an office that is off for the person or where they are a guest is never chosen. Leaving an organisation resets a workspace setting pointing to it.
