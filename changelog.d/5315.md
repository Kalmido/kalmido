### Changed
- #6402: office performance - `GET /api/clients` reads lists, contacts and the hours of all clients in a few shared queries instead of about 13 per client (28 statements for 5 and for 25 clients, before 70 / 330; amounts identical to the cent); a single client's card reads one time report for all its lists; `time_rows` filters the wanted lists in SQL. New `GET /api/clients?brief=1` (names only, no statistics), used by Offers & Invoices for the name check. The office figures tile keeps its cache for 300 s instead of 45 s (longer than its one-minute poll) and its fingerprint uses counters and a sum of row hashes instead of md5 over every document. Suite p21373_c_office_perf (new).
- #6357: restore of a backup - the list of rows deleted for good is derived from the core register (every kind with `trash_prune`, plus absences/sick notes and bookings by externals) instead of a hand-kept list of 11 tables, with a guard test; they are deleted again after a restore (preview and choice from #4302 unchanged). An account's pending deletion (`delete_at`, plan incl. an admin hold) survives a restore of an older backup, a deletion cancelled since stays cancelled. Office number counters are never set back by a restore (raised to the state before it), so no number is issued twice. Suite p21373_b_restore (new).

### Fixed
- #6430: a sort value of NaN / Infinity / out of range (also as text "nan", "inf", 1e400) on fields, org fields, links, saved filters, columns, projects, appointment types, pipeline deals and office parts is refused with 400 (one shared check `sort_value`, |x| <= 1e15); JSON answers never carry a bare NaN or Infinity any more (written as `null`), so one bad value can no longer stop the app from loading for everyone who sees the project. Suite p21373_a_sortnan (new).
- #6875: document flows - an admin who sets or changes the webhook address becomes the webhook's author at once, so the delivery checks their admin rights (losing them pauses the flow); saving the same address again keeps the author. Suite p21321_a_flowhook.
- #6952: MCP server - file names and subtask titles/notes are always fenced as data (the API names no author per file or subtask); the subtask snapshot (`sub_snapshot.items`) is fenced too. Agent template, in-app rules and docs/AGENTS.md updated. Suite mcp.
