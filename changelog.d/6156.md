### Changed
- Start: the app opens at once with the state kept on this device (only while "Stay signed in" holds for it) and syncs with the server behind it; the offline chip in the header says "Syncing" with the age of the state shown until the server's state is there, changes made meanwhile go through the offline queue; the offline queue is opened in parallel with the state request (#6366)
- The installed app's page `/` comes from its kept copy when the network gives no answer within 2.5 seconds; the late answer still refreshes the copy (#6366)
- Offline storage: the offline queue and the offline start state each have one place and one writer per browser (IndexedDB, or localStorage where the browser has none); a window never switches to a second copy after a failed write, a newer state or entry always wins over an older one, the register of device stores names the role of the second places and tools/check_devstore.py is red for a write outside their owner (#7595)

### Fixed
- An older window being hidden or closed no longer overwrites a newer offline start state of another window; a queue change whose storage write failed in one window is no longer lost or sent twice when another window takes the queue over; a window whose IndexedDB does not open sends its own pending changes itself (#7595)
- Test p2210_ui (#673) seeds the copy stamp of its offline state, required since the one write gate of #6500 (#6500)
